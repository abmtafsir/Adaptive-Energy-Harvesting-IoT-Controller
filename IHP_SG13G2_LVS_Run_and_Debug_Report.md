# 2. Initial Problem

The first attempt incorrectly passed the OpenROAD Verilog netlist directly as the KLayout LVS schematic:

```bash
klayout -b \
-r ~/OpenROAD-flow-scripts/flow/platforms/ihp-sg13g2/lvs/sg13g2.lvs \
-rd input=6_final.gds \
-rd schematic=6_final.v \
-rd topcell=adaptive_energy_controller \
-rd run_mode=deep \
-rd report=6_final_lvs.lvsdb
```

This produced:

```text
'M' element must have four nodes
```

### Cause

`6_final.v` is **Verilog**, but the IHP LVS deck uses a KLayout SPICE reader.

Therefore:

```text
Verilog != SPICE/CDL
```

The final Verilog had standard-cell instances such as:

```text
sg13g2_inv_1
sg13g2_nand2_1
sg13g2_nor2_1
sg13g2_dfrbpq_1
```

while the IHP CDL contains transistor-level `.SUBCKT` definitions for those cells.

# 5. Power-Pin Problem

The first SPICE conversion still failed because Yosys omitted physical standard-cell power pins.

Example:

```spice
X0 clknet_leaf_11_clk _0105_ _0238_ net284 sg13g2_dfrbpq_1
```

The IHP CDL definition expects additional power connections such as:

```text
VDD
VSS
```

The initial simplistic solution of blindly adding `VDD VSS` to every instance caused another pin-count mismatch because different cells have different pin counts.

### Correct solution

The final `6_final_lvs.sp` was generated by parsing the actual `.SUBCKT` pin count from:

```text
sg13g2_stdcell.cdl
```

and adding the required power connections so each standard-cell instance matches its CDL definition.

This is important:

> Do not blindly append the same number of pins to every standard cell. Use the actual CDL definition for each cell.

# 6. Top-Level Circuit Problem

After correcting the cell pin counts, KLayout successfully parsed the SPICE but reported:

```text
Can't find a schematic counterpart for the top cell
adaptive_energy_controller
- use 'same_circuit' to establish a correspondence
```

### Cause

The Yosys SPICE output consisted of top-level `X` instances but did not provide the required top-level:

```spice
.SUBCKT adaptive_energy_controller ...
```

Therefore KLayout could not establish correspondence between:

```text
Layout:
adaptive_energy_controller
```

and:

```text
Schematic:
adaptive_energy_controller
```

# 11. Common LVS Errors and Fixes

## Error 1

```text
'M' element must have four nodes
```

### Meaning

A Verilog file was supplied to the SPICE reader.

### Fix

Do not use:

```text
schematic=6_final.v
```

Use a SPICE/CDL reference netlist:

```text
schematic=6_final_lvs_ref.cir
```

---

## Error 2

```text
Pin count mismatch between circuit definition and circuit call:
6 expected, got 4
```

### Meaning

A standard-cell CDL definition requires more pins than the Yosys-generated instance provides.

### Fix

Add the required physical power connectivity according to the cell's CDL definition.

---

## Error 3

```text
Pin count mismatch between circuit definition and circuit call:
6 expected, got 3
```

### Meaning

A blanket pin-appending method was incorrectly applied to cells with different pin structures.

### Fix

Generate the corrected SPICE using the actual `.SUBCKT` pin list/count for each cell.

Do **not** blindly append `VDD VSS` to every instance.

---

## Error 4

```text
Can't find a schematic counterpart for the top cell
adaptive_energy_controller
```

### Meaning

The reference SPICE does not contain a top-level circuit named:

```text
adaptive_energy_controller
```

### Fix

Wrap the gate-level instances in:

```spice
.SUBCKT adaptive_energy_controller ...
...
.ENDS adaptive_energy_controller
```

# 13. If LVS Reports Mismatches

Once the structural parsing issues are solved, any remaining LVS errors should be treated as actual layout/reference mismatches.

Typical categories:

| LVS Result | Likely Cause |
|---|---|
| Missing device | Layout extraction missed a device |
| Extra device | Unexpected layout geometry/device |
| Net mismatch | Routing/connectivity problem |
| Pin mismatch | Top-level pin naming/connectivity |
| Device parameter mismatch | Incorrect extracted device dimensions/type |
| Missing circuit | Incorrect SPICE hierarchy |
| Cell mismatch | Incorrect CDL/library definition |
| Power net mismatch | VDD/VSS connectivity issue |

### Debug strategy

1. Confirm the top cell.
2. Check total device/cell counts.
3. Check top-level pins.
4. Check VDD/VSS connectivity.
5. Check missing/extra nets.
6. Check missing/extra devices.
7. Only then investigate individual geometry.

# 14. DRC vs LVS

A clean DRC and a clean LVS are different checks.

### DRC

Checks whether the physical layout obeys the IHP SG13G2 design rules.

```text
Layout → DRC rules
```

### LVS

Checks whether the extracted physical connectivity corresponds to the intended circuit.

```text
GDS → extracted netlist
              ↕
        reference netlist
```

Therefore:

```text
DRC CLEAN
```

does **not automatically mean**

```text
LVS CLEAN
```

Both should be reported separately.
